# 宣 Xuan · 纸感编辑风的 Web 界面约定 v0.1

一句话主张：**层级靠字阶和留白，不靠颜色和阴影。**

宣是一套为"AI agent 为主执行"而写的设计系统 starter：领地是浏览器里承载文字的页面（博客、产品页、文档站），气质是纸感编辑风。

## 文件

| 文件 | 作用 |
|---|---|
| `tokens.css` | 唯一事实来源。全项目唯一允许出现色值的地方 |
| `SKILL.md` | 给 AI 读的完整约定：铁律、决策表、反面示例、兜底条款 |
| `verify.mjs` | 每条铁律至少一个自动检查。零依赖，Node 18+ |
| `index.html` | 用系统写成的介绍页，也是活样本（自身通过 verify） |

## 快速开始

1. 页面里引入 `<link rel="stylesheet" href="tokens.css">`，颜色只用 `var(--token)`。
2. 把 `SKILL.md` 交给你的 agent（放进 Claude Code 的技能目录，或直接贴进系统提示）。
3. 交付前运行 `node verify.mjs`，报错清零。

## 三条铁律

1. **一种主色，只给值得被记住的地方。** 链接、当前态、关键数字、焦点 ring，面积不超过 5%。
2. **三档暖灰，各司其职。** 纸三档、线两档、墨三档，各有使用权限；禁冷灰，禁裸色值。
3. **层级靠字号与字族，不靠加粗和阴影。** 中文标题 500 封顶，禁硬阴影，圆角上限 12px。

## 它是怎么定义出来的（推导链）

```
领地 → 主张 → 铁律 → token → 决策表 → 验证
```

每一层从上一层严格推导：领地决定什么算"层级问题"；主张给出裁判标准；铁律是主张的可判定版本；token 是铁律的翻译；决策表是 token 的组合；verify 是铁律的执行臂。

自检方法——**可追溯性测试**：随机挑一条规则问"你从哪来"。token 要能爬到铁律，铁律要能爬到主张，主张要能爬到领地；爬不上去的规则一律删掉。例如"中文标题 500 封顶"（铁律，理由：中文缺少中间字重，合成加粗发糊）长出字阶 token，长出决策表的"强调一个词用 serif 或主色、不加粗"，长出 verify 的 X003 检查——一条规则贯穿五层，系统才立得住。

下面三处是刻意留下的占位，改完它们，这套系统才是"你的"：

1. **名字**：「宣 Xuan」取自宣纸。换成一个对你有含义的词——名字要能反过来当裁判。
2. **主色**：`tokens.css` 里的赭石 `--accent` 是占位。用反推法定：收集 5 个你觉得对味的产物，回答五组二选一（暖冷 / 衬线 / 一色多色 / 方圆 / 疏密），从中选出你自己的色。
3. **主张**：换成你自己的"我们 ____，不 ____"句式，检验标准是——没读过系统的人凭这一句话就能判断设计"像不像你的"。

暗色变量、Tailwind v4 `@theme` 映射、更多组件样例、反面样本扩充。v0.1 刻意不做——先让三条铁律在任何页面里都站得住。
