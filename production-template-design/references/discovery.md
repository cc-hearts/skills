# Discovery Questions

Use one focused round. Ask only questions that materially change the design.

## Product

- What is the product name and literal category?
- Who is the primary user, and what are they trying to complete?
- Is this a working product, a starter template, a component showcase, or a sales page?
- What is the primary conversion action?

## Scope

- Which screens, sections, or workflows are required?
- Which workflow should receive the deepest interaction detail?
- What content is confirmed, and what must remain an assumption?
- Is pricing, social proof, or a roadmap available, or should those sections be omitted?

## Design Context

- Is there an existing codebase, UI kit, design system, Figma file, screenshot, or reference site?
- Which design system is binding?
- Which brand colors, typefaces, icons, and assets must be used?
- Which visual directions are explicitly unwanted?

## Fidelity And Variations

- Is the target a wireframe, high-fidelity design, interactive prototype, or production implementation?
- Should the work produce one resolved direction or multiple comparable variations?
- If variations are wanted, should they explore layout, visual style, interaction, copy, or motion?

## Technical Constraints

- Which framework and styling method should be used?
- Must the deliverable support light/dark themes?
- Which desktop and mobile viewports matter?
- Where should files be saved?
- Must the result work offline or may it use external services?

## Suggested Compact Question Round

1. Confirm product, audience, and primary action.
2. Confirm required sections and the workflow to demonstrate.
3. Confirm design system, brand assets, and references.
4. Confirm light/dark and responsive requirements.
5. Confirm one direction versus variations.
6. Confirm output location and implementation stack.

When the user already answered an item, record it instead of asking again.
